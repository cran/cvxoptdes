Linear model optimal design

2026-10-18

Getting started

Optimal designs for linear models are calculated using the R6-class lm_design. When initializing a design object with lm_design$new(), the minimal required inputs are a (discrete) candidate design grid and a one-sided linear model formula:

library(cvxoptdes)

## 3 factors w/ 5, 5 and 3 levels
data <- expand.grid(
  x1 = -2:2,
  x2 = -2:2,
  x3 = -1:1
)

design <- lm_design$new(
  formula = ~(x1 + x2 + x3)^2 + I(x1^2) + I(x2^2) + I(x3^2),   ## full quadratic model
  data = data    ## design points
)

design$data

The $optimize() method returns the weights assigned to each design point in design$data, as well as the optimized value of the selected design criterion, which upper bounds the criterion value for any integer optimal design.

Use the $round() method to round the approximate optimal design to an exact (integer) design with a given number of observations. If method = "optimal", a number of repeated point-exchange procedures are executed to find an optimal exact design:

Since the point-exchange algorithm is initialized from (a rounded version of) the approximate optimal design, the required number of repeated runs of the point-exchange algorithm (n_repeats) can generally be kept low. The $round() method returns an integer design vector of the same length as design$data, the value of the design criterion and the relative efficiency with respect to the approximate optimal design. As the number of design points (m) in the exact design grows, the relative efficiency converges to 1. The above example covers the main methods to calculate an optimal design with cvxoptdes. The following sections provide additional details on the available optimization objectives and rounding procedures implemented in cvxoptdes and how to use them.

Approximate optimal design

By default, the following optimization problem is solved by the $optimize() method of an R6-object of class lm_design:

\[ \boldsymbol{w}^* = \arg \max_{\boldsymbol{w} \in \Delta^n} \Phi(M(\boldsymbol{w}\ |\ \boldsymbol{X}, \boldsymbol{v}) + \lambda I) - \alpha \cdot \boldsymbol{c}' \boldsymbol{w} \]

Here,

  • \(\boldsymbol{w} = (w_1,\ldots, w_n)'\) is the vector of (continuous) design weights, with \(w_i \in [0, 1]\) and \(\sum_{i = 1}^n w_i = 1\).
  • \(\boldsymbol{c} = (c_1,\ldots, c_n)'\) is a cost assigned to each design weight scaled by the (global) penalty parameter \(\alpha\).
  • \(M(\boldsymbol{w}\ |\ \boldsymbol{X}, \boldsymbol{v})\) is the information matrix of the linear model depending on the weights \(\boldsymbol{w}\) and the \((n \times p)\) design matrix \(\boldsymbol{X}\), and possibly a vector of fixed user weights \(\boldsymbol{v} = (v_1, \ldots, v_n)'\) in the case of weighted linear regression.
  • \(\Phi(M)\) is the design optimality criterion as a (scalar) function of the information matrix \(M\).

Given the linear model formula, the \((p \times p)\) information matrix, conditional on the error variance \(\sigma_e^2\), is given by: \[ M(\boldsymbol{w}\ |\ \boldsymbol{X}, \boldsymbol{v}) \ = \ \frac{1}{\sigma_e^2} \sum_{i = 1}^n w_i v_i \boldsymbol{x}_i \boldsymbol{x}_i' \] where \(\boldsymbol{x}_i\) is the i-th design point or the i-th row in the design matrix \(\boldsymbol{X}\) constructed with model.matrix. If \(\lambda > 0\) in the optimization problem, a ridge term is added to the diagonal of \(M\) resulting in the information matrix of a ridge linear regression model. This is particularly useful when \(n < p\) to ensure a non-singular information matrix for the evaluation of the optimality criterion \(\Phi(M)\).

When calling the $optimize() method, the penalized optimization problem is solved efficiently as a convex second-order cone program (SOCP) using the open-source Splitting Cone Solver (SCS). For D-optimal designs, the SOCP is formulated using spectral cones introduced in (Cederberg and Boyd 2025). For I-, A-, and G-optimal designs, the SOCP formulations of (Sagnol and Harman 2015) are used. At the moment of writing, the $optimize() method supports the following optimality criteria:

D-optimality : Maximize the volume (determinant) of the information matrix \(M\), or equivalently minimize the volume of the confidence ellipsoid of the parameter estimates. For D-optimality, the logarithm of the D-criterion is used for optimization:

\[ \Phi(M) = \log\left(\det(M)^{1/p}\right) \]

Exact optimal design

Optimal rounding

As demonstrated in the initial example, the $round() method is used to round an approximate (optimal) design to an exact integer design with a given number of observations. The default rounding method is "optimal" rounding, which executes a number (n_repeats) of repeated Fedorov point-exchange procedures (Fedorov 1972) starting from randomly sampled versions of the distribution of approximate design weights, or from efficiently rounded designs (Pukelsheim and Rieder 1992) if the size of the exact design is sufficiently large. The optimality criterion is recycled from the "criterion" attribute in the design weights vector (design$design_weights) populated by $optimize(), but can be overridden by passing a new criterion to $round() itself. Instead of starting the rounding procedure from a rounded version of the approximate design in design$design_weights, it is also possible to provide a custom weight vector via the design_weights argument or to round from a random initial design by setting design_weights = FALSE.

(exact_design <- design$round(m = 15, method = "optimal", criterion = "I", design_weights = design_weights, n_repeats = 100, seed = 1))

Efficient rounding

The "efficient" rounding method is included for completeness only, as this is used for (efficient) initial rounding of the approximate design weights to serve as a starting point for the point-exchange algorithm in "optimal" rounding. The "efficient" rounding method requires the number of requested design points m to be larger than (or equal to) the size of the support of the approximate design.

Distance-based rounding

The "dist-sum" and "dist-min" rounding methods maximize the distances between rows of the candidate design matrix, or equivalently, maximize exploration of the design space. The rounded designs are calculated using point-exchange methods that are independent of the selected design criterion. The "dist-sum" rounding procedure maximizes the total pairwise (Euclidean) distance between design matrix rows of the integer design. The "dist-min" rounding procedure maximizes the minimum pairwise (Euclidean) distance between design matrix rows. These distance-based methods are primarily of interest for small rounded designs, where the number of requested design points m is (much) smaller than the total number of candidate design points, i.e. \(m \ll n\).

Parallel evaluation

The repeated point-exchange algorithms run by the $round() method can be executed in parallel using mirai. The number and type of parallel background R processes is configured by the user before calling $round() with mirai::daemons(). If daemon connections are available, $round() automatically runs in asynchronous mode using the configured daemons:

library(mirai)

daemons(n = parallel::detectCores() / 2, seed = 1)     ## use half the number of available cores

design$round(m = 100, method = "optimal", n_repeats = 1000)

daemons(0)   ## close daemons

Remark: the implemented exchange algorithms depend heavily on low-level BLAS and LAPACK routines. If the BLAS/LAPACK routines already execute on multiple threads, this may interfere with the asynchronous evaluation of mirai. In this case, it is recommended to restrict BLAS/LAPACK to a single thread by setting the environment variables OPENBLAS_NUM_THREADS, MKL_NUM_THREADS or OMP_NUM_THREADS, depending on the BLAS library being used. In addition, there is a small overhead in populating the environments of the background R processes to prepare the evaluations. In rare cases, this leads to a higher computation time than sequential evaluation in the main R process, especially when n_repeats is small or the execute time of a single repeat of the exchange algorithm is almost negligible.

Penalized optimal design

By penalized or weighted optimal design, we refer to optimization of the design criterion subject to a user-defined cost penalty or weight assigned to each candidate design point. Heterogeneous weights or costs can be included in the design optimization problem in two ways; either through the weight vector \(\boldsymbol{v} = (v_1,\ldots,v_n)'\) or through the cost vector \(\boldsymbol{c} = (c_1,\ldots,c_n)'\). The weights \(\boldsymbol{v}\) are incorporated as multiplicative terms on the level of the information matrix, whereas the costs \(\boldsymbol{c}\) are penalizing the optimality criterion value using an additive penalty term. Both options have intuitive interpretations; a heterogeneous weight vector \(\boldsymbol{v}\) produces the optimal design of a weighted linear regression model. For a non-zero cost vector \(\boldsymbol{c}\), the optimization problem above is the dual form (with Lagrange multiplier \(\alpha\)) of the cost-constrained design optimization problem:

\[ \boldsymbol{w}^* = \arg \max_{\boldsymbol{w} \in \Delta^n} \Phi(M(\boldsymbol{w}\ |\ \boldsymbol{X}, \boldsymbol{v}) + \lambda I), \quad \quad \text{subject to} \quad \boldsymbol{c}'\boldsymbol{w} \leq B \] for some design budget \(B\). An advantage of using the multiplicative weights \(\boldsymbol{v}\) is that the weighted optimal design is invariant under scaling of \(\boldsymbol{v}\). This is not the case when scaling the penalty parameter \(\alpha\) or the costs \(\boldsymbol{c}\), which change the contribution of the additive penalty term in the optimization problem.

To add costs \(\boldsymbol{c} = (c_1,\ldots,c_n)'\) to the optimization problem, we can either re-initialize the design object with lm_design$new() (including a cost argument) or update the existing object:

## assign c = 1 if x3 = 1, and c = 0 otherwise
design$update(
  cost = ~pmax(x3, 0),
  alpha = 1
)

The $update() method accepts the same arguments as lm_design$new(), which means that the linear model (formula) or the candidate design grid (data) can also be updated if needed. Here, we assigned a cost \(c_i = 1\) to all design points with x3 = 1 and a cost \(c_i = 0\) otherwise. This could be a scenario where the design points with level x3 = 1 are more expensive or time-consuming to evaluate. The penalty parameter \(\alpha\) is set to \(\alpha = 1\). Increasing \(\alpha\) increases the importance of the assigned costs relative to the optimality criterion \(\Phi(M)\).

To evaluate the design criterion excluding the cost penalty term, use the $crit() method with alpha = FALSE. By default, the criterion value is returned for the approximate design present in the $design_weights field:

Similarly, weights \(\boldsymbol{v} = (v_1, \ldots, v_n)'\) can be added to the optimization problem by updating the existing object using the weights argument:

## assign v = 1 if x3 = 1, and v = 0.1 otherwise
design$update(
  weights = ~pmax(x3, 0.1),
  cost = NULL

Stratified optimal design

The formulation of the approximate optimal design problem as a convex second-order cone program allows for straightforward extension by extra convex (cone) constraints. One relevant (linear) equality constraint is that of a stratified optimal design. Consider a partitioning of the candidate design grid into individual (disjoint) strata \(\mathcal{X}_1,\ldots,\mathcal{X}_S\), then we solve the optimal design problem subject to the constraint that each stratum is represented with a given proportion \(p_1,\ldots,p_S\) (\(\sum_s p_s = 1\)):

\[ \begin{aligned} \boldsymbol{w}^* \ = \ & \arg \max_{\boldsymbol{w} \in \Delta^n} \Phi(M(\boldsymbol{w}\ |\ \boldsymbol{X}, \boldsymbol{v}) + \lambda I) - \alpha \cdot \boldsymbol{c}'\boldsymbol{w}, \\ & \text{subject to } \sum_{\{i\ :\ \boldsymbol{x}_i \in \mathcal{X}_s\}} w_i = p_s, \quad \text{for } s = 1,\ldots,S \end{aligned} \] To include stratification constraints in the optimal design problem, the $stratify() method is used. The partitioning into individual strata can be passed as a single factor variable or a one-sided formula containing multiple factors. In the second case, the strata are defined by the unique levels obtained from the interaction() of all factors in the formula.

## drop weights term
design$update(weights = NULL)

## add stratification constraints
design$stratify(
  strata = ~x3,
  proportions = c(1/4, 1/2, 1/4)

Design orthogonality constraints

The alias-optimality criterion minimizes the absolute cosine similarity between columns of the design matrix \(\boldsymbol{X}\) subject to the design weights \(\boldsymbol{w} = (w_1,\ldots,w_n)'\). Instead of minimizing the cosine similarity, it is also possible to add explicit constraints on the absolute cosine similarities, which are representable as (convex) rotated second-order cone inequalities. For design columns \(q\) and \(r\), and a given constraint value \(\rho_{qr} \in [0, 1]\), we can include the following constraint in the design optimization problem:

\[ \left| \frac{\langle \boldsymbol{w} \boldsymbol{x}_{.q}, \boldsymbol{x}_{.r} \rangle}{\Vert \sqrt{\boldsymbol{w}} \boldsymbol{x}_{.q} \Vert \Vert \sqrt{\boldsymbol{w}} \boldsymbol{x}_{.r} \Vert} \right| \ \leq \ \rho_{qr} \]

To illustrate with an example, it is often desirable for the main effects columns (x1, x2, x3) to be orthogonal to all other design columns to ensure identifiability of the main effects parameters. Orthogonality constraints are specified using the orthogonal argument in lm_design$new() or $update() in the form of a three-part formula, e.g. x1 + x2 + x3 ~ . ~ 0. The first part (x1 + x2 + x3) defines all design columns \(\boldsymbol{x}_{.q}\) passed as first argument in the orthogonality constraint using linear model formula notation. The second part (.) defines all design columns \(\boldsymbol{x}_{.r}\) passed as second argument in the orthogonality constraint using linear model formula notation. The third part is optional and specifies the constraint value \(\rho_{qr}\) for the set of selected design columns. If only a two-part formula is provided, \(\rho_{qr}\) is set to zero. A list of formulas can be passed to the orthogonal argument to stack different constraints for different subsets of design columns. To verify that all orthogonality constraints are parsed as expected, the $orthogonal field can be inspected, which returns the \((p \times p)\) constraint matrix \((\rho_{qr})_{q,r}\):

## orthogonal main effects wrt all other columns
design$update(

Sparse optimal design

The optimized approximate design is in fact identical to an unconstrained D-optimal design, as the optimal solution remains feasible also with the added orthogonality constraints. More interesting is enforcing the orthogonality constraints on a smaller (or sparser) set of support points. Penalties that promote sparsity of the design weight vector \(\boldsymbol{w} = (w_1,\ldots,w_n)'\) are generally not convex. For this reason, a sequential convex approximation procedure is implemented, substituting (concave) sparseness penalties by linearized (convex) costs on the design weights.

The sequential convex approximation procedure is available through the $sparsify() method, which runs several iterations of $optimize(), each iteration updating the cost term \(\alpha \cdot \boldsymbol{c}' \boldsymbol{w}\) based on the selected (sparsity promoting) reweighting function. Ideally, the maximum number of reweighting iterations is large enough for the weight vector to converge to a stable solution.

## set sparseness penalty
design$update(alpha = 0.75)

Besides the orthogonal argument, two other new arguments are used above: zeros and col_means.

The zeros argument allows to specify the proportion of zeros for sets of design columns in the form of one or more two-part formulas (e.g. ~ x1 + x2 + x3 + x4 + x5 + x6 ~ 0.125), included as extra (linear) equality constraints when optimizing the design. The left-hand side of each formula defines a set of design columns using linear model notation. The right-hand side specifies the proportion of zeros for the given set of design columns. If a one-part formula is provided as above, the proportion of zeros for each of the selected design columns is constrained to be the same, but no exact proportion is imposed. For exact designs, the zeros argument is only taken into account when using the "orthogonal" rounding method, in which case the proportions are converted to an exact number of zeros based on the requested design size \(m\).

The col_means argument constrains the designs column averages for sets of design columns. Similar to the orthogonal and zeros arguments, col_means accepts one or more two-part formulas (x1 + x2 + x3 + x4 + x5 + x6 ~ 0). The left-hand side of each formula selects the design columns and the right-hand side the requested column average subject to the optimized design. For exact designs, the col_means argument is only taken into account when the "orthogonal" rounding method is used.

Computational effort

As the number of columns \(p\) in the design matrix \(\boldsymbol{X}\) grows, it becomes computationally more expensive (i.e. more time-consuming) to solve the MILP and find a valid orthogonally constrained design. As of HiGHS version 1.15.0, the MILP can be solved in parallel using multiple CPU cores to reduce the runtime. Another option is to export the MILP as a generic MPS file using the highs_write_mps argument when calling $round(). This allows to solve the MILP using an external (commercial) solver, e.g. CPLEX, Gurobi, Mosek, or if a GPU is available, using the open-source cuOpt solver.
